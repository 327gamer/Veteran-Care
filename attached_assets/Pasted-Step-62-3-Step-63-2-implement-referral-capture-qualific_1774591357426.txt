TASK A — referral capture from referral code
Implement backend logic to support incoming referral code usage.

Requirements:
- when a new user lands/signs up using a referral code, the system must be able to associate that referral code with the newly created user
- store a pending referral record in user_referrals
- fields should include:
  - referrer_user_id
  - referred_user_id
  - referral_code
  - status = pending initially
- prevent self-referral where possible
- prevent duplicate rewarded referral relationships
- if there is already an existing session/onboarding/start flow pattern, hook into it cleanly instead of inventing a new architecture

IMPORTANT:
If exact signup timing makes immediate referred_user_id capture difficult, implement the cleanest launch-safe backend pattern already compatible with the current auth/onboarding flow, and explain what hook point was used.

TASK B — qualification helper/service
Create a helper/service function that can be called once the referred user meets launch qualification.

Suggested name:
- qualifyReferralForUser(userId) or equivalent

Behavior:
- find pending referral tied to the referred user
- verify it is not already qualified/invalid
- verify user is not self-referring
- mark referral as qualified
- set qualified_at timestamp
- create exactly one row in referral_entries
- set:
  - user_id = referrer user
  - referral_id = qualifying user_referrals.id
  - entry_month = current YYYY-MM
  - entry_count = 1
  - source = 'referral'
- must be idempotent:
  - if called multiple times, do not create duplicate entries
