✅ Step 7.2 – Rotation Performance Visibility

❌ NOT billing changes  
❌ NOT Stripe changes  
❌ NOT reassignment changes  
❌ NOT automation  

This step is STRICTLY visibility + fairness monitoring.

-------------------------------------
OBJECTIVE
-------------------------------------

Allow admin to verify that the round-robin system is distributing leads fairly within each routing scope.

System must answer:

- Are partners receiving balanced distribution?
- Is one partner getting too many leads?
- Is rotation behaving correctly per scope?
- Is fairness improving or drifting over time?

-------------------------------------
REQUIREMENT 1 — ROTATION PERFORMANCE METRICS
-------------------------------------

Build a lightweight endpoint or query:

GET /api/admin/rotation-performance

Return grouped by routing_scope_key:

For each scope:

- routing_scope_key
- number_of_eligible_partners
- total_rotated_leads
- last_assigned_partner_id
- last_assigned_at

Nested per partner:

- partner_id
- partner_name
- leads_assigned
- percentage_share

IMPORTANT:
- ONLY include leads where routing_method = 'rotated'
- EXCLUDE direct assignments completely

-------------------------------------
REQUIREMENT 2 — FAIRNESS STATUS LOGIC
-------------------------------------

Add derived field:

- fairness_status

Values:

- balanced
- slight_skew
- imbalance_detected
- low_sample (NEW – critical)

-------------------------------------
FAIRNESS LOGIC
-------------------------------------

IF total_rotated_leads < 5:
→ fairness_status = low_sample

ELSE:

Calculate expected share:
→ 1 / number_of_partners

Measure max deviation from expected share:

- balanced:
  deviation ≤ 15%

- slight_skew:
  deviation between 15%–30%

- imbalance_detected:
  deviation > 30%

Keep logic lightweight and adjustable.

-------------------------------------
REQUIREMENT 3 — MINIMUM SAMPLE PROTECTION
-------------------------------------

CRITICAL:

Do NOT flag imbalance when:
- total_rotated_leads < 5

Instead:
→ show "LOW SAMPLE" (neutral / gray)

This prevents false alarms during early usage.

-------------------------------------
REQUIREMENT 4 — ADMIN VISIBILITY

NO dashboards

REQUIREMENT 5 — FAIRNESS BADGES
-------------------------------------

Use simple color indicators:

-------------------------------------
REQUIREMENT 6 — FILTER SUPPORT

Allow admin filtering:
