❌ NOT automation

This step defines how batch size should evolve safely over time.

-------------------------------------
OBJECTIVE
-------------------------------------

Help admin determine:

- when it is safe to increase batch size
- when batch size should be reduced
- how different categories behave at scale
- how partner performance affects safe scaling

This builds structured scaling discipline without automation.

-------------------------------------
REQUIREMENT 1 — BATCH EXPANSION STATE
-------------------------------------

Add derived field:

- batch_expansion_state

Values:

- conservative
- stable
- expansion_ready
- expansion_risk

-------------------------------------
REQUIREMENT 2 — EXPANSION LOGIC
-------------------------------------

Use recent batch performance:

expansion_ready:
- SAFE performance
- stable or improving trend
- at least 2–3 successful batches

stable:
- SAFE or STABLE performance
- no significant failures

conservative:
- CAUTION state
- or limited batch history

expansion_risk:
- declining trend
- failure spikes
- repeated failures

Keep logic lightweight and adjustable later.

-------------------------------------
REQUIREMENT 3 — CATEGORY-SPECIFIC SIGNALS
-------------------------------------

Add visibility for:

- category_batch_performance

Examples:

- Housing → SAFE / expansion_ready
- Financial → NO DATA / conservative

Purpose:
identify which categories scale safely.

-------------------------------------
REQUIREMENT 4 — PARTNER-SPECIFIC SIGNALS
-------------------------------------

Add visibility for:

- partner_batch_performance

Examples:

- Tri-County → SAFE
- Boot Print → RISK

Purpose:
identify which partners support scaling.

-------------------------------------
REQUIREMENT 5 — GUIDANCE TEXT
-------------------------------------

Display guidance:

expansion_ready:
→ “You can cautiously increase batch size.”

stable:
→ “Maintain current batch size.”

conservative:
→ “Increase slowly and monitor closely.”

expansion_risk:
→ “Reduce batch size and review failures.”
