- accepted
- declined
- need_info
- completed

-------------------------------------
REQUIREMENT 2 — RESPONSE STATUS UPDATE RULES
-------------------------------------

When a valid action is clicked:

System MUST:
- update navigator_requests.response_status
- set response_at = current timestamp
- preserve assigned_at
- preserve email_sent / email_sent_at
- record who responded if safely available

Status mapping:
- Accept → accepted
- Decline → declined
- Need Info → need_info
- Completed → completed

No other values allowed.

-------------------------------------
REQUIREMENT 3 — IDEMPOTENT + SAFE BEHAVIOR
-------------------------------------

The action system must be safe against repeated clicks or weird email behavior.

Rules:
- repeated clicks on same action must not corrupt data
- invalid token must be rejected
- action on nonexistent request must return safe error
- no duplicate records
- no unrelated request updates

State rules:
- completed remains terminal
- accepted can move to completed
- need_info can move to accepted or completed
- declined remains declined unless manually changed by admin
